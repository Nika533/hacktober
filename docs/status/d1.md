## Notes — D1-00 findings

Environment: Windows 11 Pro 10.0.26300, **one display** (1280×800 DIP,
scaleFactor 2 → 2560×1600 physical), Electron 44.9.0 / Chromium 152, Node 24.
Mouse input in the spikes was injected with `SetCursorPos` / `mouse_event`,
not a physical mouse — flagged where it matters.

### 1. Sandboxed transparent buddy, click-through, CSP header

| Checked | Result |
|---|---|
| `sandbox: true` + `contextIsolation: true` preload with `contextBridge` | **Works.** `window.api` exists, `ipcRenderer.invoke` round-trips, `require` and `process` are undefined in the page |
| Transparent, frameless, always-on-top window; `capturePage()` alpha | **Works.** 78% of pixels transparent in the PNG, so screenshot-based e2e checks keep working |
| Clicks on fully transparent pixels | **Pass through natively**, even with `setIgnoreMouseEvents(false)` (layered-window per-pixel hit testing) |
| `setIgnoreMouseEvents(true)` on opaque pixels / restore with `(false)` | **Works** both ways (0 mousedowns while ignoring, 1 after restore) |
| `setIgnoreMouseEvents(true, { forward: true })` delivering `mousemove` | **Not with injected input** (0 events over an 800 ms dwell). **Works with a physical mouse:** the legacy app relies on exactly this to flip click-through off when the cursor reaches a `[data-hit]` element, and hover/click on the pill buttons worked for a real user. Treat as hardware-only; e2e cannot exercise it |
| CSP as a response header for `loadFile` (`file://`) via `session.webRequest.onHeadersReceived` | **Fires and is enforced.** Inline `<script>` and `<style>` blocked (`script-src-elem` / `style-src-elem` violations); an external same-dir script ran |
| CSP via custom scheme `hoot://` (`registerSchemesAsPrivileged` + `protocol.handle` returning a `Response` with the header) | **Works identically**, and gives a proper secure, standard origin |

**Decisions for D1-12/D1-14:**
- Serve renderers in production over `hoot://` with the CSP header; no CSP
  meta tags. Keep the `onHeadersReceived` variant as the dev fallback for the
  Vite URL.
- Click-through design: keep the per-pixel transparency as the primary
  mechanism, keep the `forward:true` + `[data-hit]` flip for hover, **and add a
  main-side fallback**: the cursor poller we already need for the owl's eyes
  (`screen.getCursorScreenPoint()` at ~20–30 Hz while visible) compares the
  cursor to renderer-reported hit regions and toggles `setIgnoreMouseEvents`
  itself. That removes the single point of failure if forwarding ever stops
  working, and it makes the behaviour testable without a physical mouse.
- Manual QA item for every buddy PR: hover and click with a real mouse.

### 2. Mica Studio

| Checked | Result |
|---|---|
| `titleBarStyle: 'hidden'` + `titleBarOverlay` (height 44) | `navigator.windowControlsOverlay.visible === true`; `getTitlebarAreaRect()` = `{x:0, y:0, width:502, height:44}` on a 640 DIP window, so the caption buttons take **~138 DIP on the right** |
| CSS `env(titlebar-area-x/y/width/height)` | Resolves correctly (0 / 0 / 502 / 44). `getComputedStyle` can't read `env()`; measure a probe element instead |
| `backgroundMaterial: 'mica'` and live `setBackgroundMaterial('acrylic' | 'none')` | All three render visibly different frames; `'none'` is an opaque flat surface, our fallback when Mica isn't available |
| `nativeTheme.themeSource = 'dark'` → `prefers-color-scheme` in a sandboxed renderer | **Flipped in the spike** (media query changed, `change` listener fired). This contradicts what the legacy app observed with `sandbox:false` (media query stayed light). Cause unknown; **don't rely on it** — keep the explicit `darkMode` state broadcast from main as the source of truth, with the media query as fallback |
| `setTitleBarOverlay({ symbolColor })` at runtime | Accepted without error. In the dark screenshot the glyphs are invisible because the spike left `symbolColor` dark — the app must update it on theme change, as legacy does |
| Desktop screenshots of Studio for QA | Windows refuses the focus steal; use `setAlwaysOnTop(true, 'pop-up-menu')` + `moveTop()` before `CopyFromScreen`, then restore |

### 3. `desktopCapturer` and DPI

| Checked | Result |
|---|---|
| `display_id` ↔ `screen.getAllDisplays()[i].id` | Exact string match on this machine (`'1496022656'`) |
| `thumbnailSize` = physical size (2560×1600) | Returns exactly that; `thumb.width / display.bounds.width === scaleFactor` (2) |
| `thumbnailSize` larger than physical (5120×3200) | **Upscaled, not capped.** Never infer DPI from the returned size alone; compute the crop ratio from `image.width / display.bounds.width` (legacy already does) |
| Tiny request (320×320) | 320×200, aspect-preserving fit |
| Latency | **~2.9 s cold** for the first `getSources`, ~0.5 s afterwards regardless of size |
| Black-screen detection on a 32×32 downscale | Works (`maxChannel 241`) |
| Multiple monitors / mixed DPI | **Not verified** — only one display attached. Needs a two-monitor machine before M2's capture gate; the per-display ratio approach is the right shape for it |

**Decision for D1-20:** pre-warm `desktopCapturer.getSources` once with a tiny
thumbnail a few seconds after launch (idle), so the first real capture isn't
~3 s; keep the ratio-from-image crop math; test on a second monitor when one
is available.

### 4. Named pipe server in Electron main

| Checked | Result |
|---|---|
| `net.createServer().listen('\\\\.\\pipe\\hoot-spike-<user>')` in main | Works; a separate Node process connected and round-tripped a 4-byte LE length-prefixed JSON frame in **2 ms** |
| Second server on the same name | `EADDRINUSE` (hard error, no silent takeover) |
| `server.close()` | Frees the name immediately; rebind on the next tick succeeded |

**Decision for D1-10 (lifecycle hook for C-20):** start the bridge server
after `whenReady` and after winning the single-instance lock; stop it in
`will-quit`; treat `EADDRINUSE` as "another Hoot is running" and exit.

### 5. Lifecycle

| Checked | Result |
|---|---|
| `safeStorage.isEncryptionAvailable()` | **false before `ready`, true after.** Never touch secrets at module init |
| `safeStorage.getSelectedStorageBackend()` | Does not exist on Windows (undefined); don't gate on it |
| Single-instance lock + `second-instance` argv | Second process gets no lock and exits; the first receives `['…electron.exe', '--hidden', '--spike-arg=42', '--allow-file-access-from-files', '<app dir>']`. In dev Electron inserts its own flags and puts the app path last, so parse flags by prefix, never by position |
| Flush-before-quit (`before-quit` → `preventDefault` → async flush → `app.quit()` again) | Works: marker file written, process exited exactly once, `before-quit` fired twice. A "flushed" guard flag is essential or the re-`quit()` re-enters the veto forever |

### What was not verified

- `forward: true` with a physical mouse inside a spike (only indirect evidence
  from the legacy app).
- Multi-monitor and mixed-DPI capture (one display).
- Mica on Windows 10 / builds without Mica support (`'none'` fallback exists
  but wasn't exercised on such a machine).
- Named pipe behaviour from the **installed** app under Smart App Control
  (unsigned binaries are blocked on this machine; see `AGENTS.md`).
