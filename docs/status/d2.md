## For d3: the `Renderer` contract (from `@hoot/lens-dom`)

`pdf-view`'s overlay renderer should implement `Renderer` from
`packages/lens-dom/src/render/types.ts`:

- `check(range, spec?)`: returns `{ ok: true }` or `{ ok: false, reason }`.
- `apply(range, spec)`: returns a `Mark` or `null`.
- `restore(id)`, `restoreAll()`, `get(id)`, `marks()`, `subscribe(listener)` for
  `dropped` and `reapplied` events, and `destroy()`.

A `Mark` has `id`, `spec`, `original` (the exact characters), `anchor` (the focusable
element the popover anchors to, with `aria-describedby` set) and `rects()`.

`MarkSpec` is `{ action: 'replace' | 'gloss', transform, text, highStakes?, placement? }`.
The Lens UI (D2-12) only talks to `Renderer` and `Mark`, so a PDF renderer gets the
popover, pill and keyboard map for free.

## Notes

- Mark structure: the selected nodes move into a `<hoot-lens-mark>` element and stay in the
  light DOM. The element's own shadow root renders either the rewrite (replace) or a
  `<slot>` plus the note (gloss). As a result, the page's `textContent` never changes,
  restoring means unwrapping, and the original `Text` node objects come back (merging the
  split text nodes is order-independent across marks). Rewrites are always set with
  `textContent`, never parsed as HTML.
- Ranges that cross element boundaries become one segment per parent. Only the first
  segment shows the rewrite; restore is still exact.
- Content scripts have `customElements === null`, so `hoot-lens-mark` is never defined
  as a custom element. It only uses `attachShadow`, which valid custom-element names allow.
- happy-dom (20.14.6) doesn't update live ranges on `splitText`, so `normalizeRange`
  recomputes boundaries from node references. It also has no `CSS.highlights`; the overlay
  renderer has to feature-detect it.
- Exit criterion: `tests/inline.test.ts` round-trips 300 seeded random ranges over the
  whitespace fixture (nbsp, runs of spaces, tab and newline in `pre-wrap`, emoji, CJK,
  narrow nbsp) and compares `innerHTML` and text-node identity. Verified in Chromium 156
  too: byte-identical `innerHTML` after Restore, in light and dark.
- Never touched (`src/guard.ts`): inputs, textarea, select, button, `contenteditable`, the
  textbox, searchbox, combobox and spinbutton roles, `pre`, `code`, `kbd`, `samp`,
  `blockquote`, `q`, `hidden`, `inert`, `aria-hidden`, `script` and `style`, iframes,
  media, `svg` and `math`, existing marks, and our own UI. Ranges must stay inside one
  block and under 600 characters.
- Interpretation to confirm (spec §5.4, "text inside links' accessible names"): link text
  is never replaced, and neither is a range that starts or ends inside a link. A gloss may
  cover a whole link, because the link stays intact.
- Re-render handling: after every mutation batch, each mark checks that it is intact
  (host connected, same child nodes, same text). If not, it is unwrapped quietly and a
  `dropped` event fires. If a block with the same normalized text comes back, the mark is
  re-applied from the remembered spec (`reapplied`). This happens at most 3 times per mark,
  so a page that fights us wins.
- Overlay renderer: a live `Range` clone, with the original's glyphs hidden by a
  `::highlight(hoot-lens-replace) { color: transparent }` rule (gloss tints them instead).
  The rewrite sits in a box in the shared UI shadow root. The box copies the page's
  computed font, line height and colour, follows the paragraph's flow (`text-indent` at
  the original x, corrected for half-leading), and gets the page background behind the
  rewrite. If the rewrite is longer than the original's lines, it first shrinks to
  94/88/82 % and then becomes a floating card with a shadow and hairline (spec §9.2).
  Boxes follow scroll (capture), resize and ResizeObserver, batched per animation frame.
  It drops and re-applies through the same `Lifecycle` as inline marks. Verified in
  Chromium 156: `document.body.innerHTML` is byte-identical while marked, and highlights
  are cleared after restore.
- Known overlay limits: screen readers still read the page's original in place (we don't
  add `aria-hidden` to page nodes). The rewrite box sits at the end of the tab order.
  Without the Custom Highlight API the original isn't hidden; only the rewrite's
  background covers it.
- Dynamic detection: strong markers (`data-reactroot`, `#__next`, `#__nuxt`, `#___gatsby`,
  `data-v-app`, `ng-version`, `data-server-rendered`, SvelteKit, Astro, Qwik) mean dynamic.
  So does ≥ 8 mutations/s in the first 3 s, or a weak marker (`#root`, `#app`) plus
  ≥ 1 mutation/s. `markDynamic()` lets the controller switch after repeated drops.
  Expando properties (React's `__reactContainer$…`) are invisible from the isolated
  world, so only attributes count.
- Demo: `npm.cmd run demo` in `packages/lens-dom`, then open `demo/dist/index.html`
  (`?renderer=overlay`, `&action=gloss`).
- Playwright 1.64 needs `npx.cmd playwright install chromium` (build v1248).
