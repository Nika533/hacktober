## For d3: the `Renderer` contract (from `@hoot/lens-dom`)

`pdf-view`'s overlay renderer should implement `Renderer` from
`packages/lens-dom/src/render/types.ts`:

- `check(range, spec?)`: returns `{ ok: true }` or `{ ok: false, reason }`.
- `apply(range, spec)`: returns a `Mark` or `null`.
- `restore(id)`, `restoreAll()`, `get(id)`, `marks()`, `subscribe(listener)` for
  `dropped` and `reapplied` events, and `destroy()`.

A `Mark` has `id`, `spec`, `original` (the exact characters), `anchor` (the focusable
element the popover anchors to, with `aria-describedby` set) and `rects()`.

`MarkSpec` is `{ action: 'replace' | 'gloss', transform, text, highStakes?, placement? }`.
The Lens UI (D2-12) only talks to `Renderer` and `Mark`, so a PDF renderer gets the
popover, pill and keyboard map for free.

## Notes

- Mark structure: the selected nodes move into a `<hoot-lens-mark>` element and stay in the
  light DOM. The element's own shadow root renders either the rewrite (replace) or a
  `<slot>` plus the note (gloss). As a result, the page's `textContent` never changes,
  restoring means unwrapping, and the original `Text` node objects come back (merging the
  split text nodes is order-independent across marks). Rewrites are always set with
  `textContent`, never parsed as HTML.
- Ranges that cross element boundaries become one segment per parent. Only the first
  segment shows the rewrite; restore is still exact.
- Content scripts have `customElements === null`, so `hoot-lens-mark` is never defined
  as a custom element. It only uses `attachShadow`, which valid custom-element names allow.
- happy-dom (20.14.6) doesn't update live ranges on `splitText`, so `normalizeRange`
  recomputes boundaries from node references. It also has no `CSS.highlights`; the overlay
  renderer has to feature-detect it.
- Exit criterion: `tests/inline.test.ts` round-trips 300 seeded random ranges over the
  whitespace fixture (nbsp, runs of spaces, tab and newline in `pre-wrap`, emoji, CJK,
  narrow nbsp) and compares `innerHTML` and text-node identity. Verified in Chromium 156
  too: byte-identical `innerHTML` after Restore, in light and dark.
- Never touched (`src/guard.ts`): inputs, textarea, select, button, `contenteditable`, the
  textbox, searchbox, combobox and spinbutton roles, `pre`, `code`, `kbd`, `samp`,
  `blockquote`, `q`, `hidden`, `inert`, `aria-hidden`, `script` and `style`, iframes,
  media, `svg` and `math`, existing marks, and our own UI. Ranges must stay inside one
  block and under 600 characters.
- Interpretation to confirm (spec §5.4, "text inside links' accessible names"): link text
  is never replaced, and neither is a range that starts or ends inside a link. A gloss may
  cover a whole link, because the link stays intact.
- Re-render handling: after every mutation batch, each mark checks that it is intact
  (host connected, same child nodes, same text). If not, it is unwrapped quietly and a
  `dropped` event fires. If a block with the same normalized text comes back, the mark is
  re-applied from the remembered spec (`reapplied`). This happens at most 3 times per mark,
  so a page that fights us wins.
- Overlay renderer: a live `Range` clone, with the original's glyphs hidden by a
  `::highlight(hoot-lens-replace) { color: transparent }` rule (gloss tints them instead).
  The rewrite sits in a box in the shared UI shadow root. The box copies the page's
  computed font, line height and colour, follows the paragraph's flow (`text-indent` at
  the original x, corrected for half-leading), and gets the page background behind the
  rewrite. If the rewrite is longer than the original's lines, it first shrinks to
  94/88/82 % and then becomes a floating card with a shadow and hairline (spec §9.2).
  Boxes follow scroll (capture), resize and ResizeObserver, batched per animation frame.
  It drops and re-applies through the same `Lifecycle` as inline marks. Verified in
  Chromium 156: `document.body.innerHTML` is byte-identical while marked, and highlights
  are cleared after restore.
- Known overlay limits: screen readers still read the page's original in place (we don't
  add `aria-hidden` to page nodes). The rewrite box sits at the end of the tab order.
  Without the Custom Highlight API the original isn't hidden; only the rewrite's
  background covers it.
- Dynamic detection: strong markers (`data-reactroot`, `#__next`, `#__nuxt`, `#___gatsby`,
  `data-v-app`, `ng-version`, `data-server-rendered`, SvelteKit, Astro, Qwik) mean dynamic.
  So does ≥ 8 mutations/s in the first 3 s, or a weak marker (`#root`, `#app`) plus
  ≥ 1 mutation/s. `markDynamic()` lets the controller switch after repeated drops.
  Expando properties (React's `__reactContainer$…`) are invisible from the isolated
  world, so only attributes count.
- Lens UI (D2-12):
  - **Popover:** original (or the note, for a gloss), Restore (Remove note), I knew this,
    Explain more, a transform footer, Copy rewritten, and the high-stakes note. It is a
    `role=dialog` that grows from the mark (`transform-origin` at the anchor) and exits
    along the same path.
  - **Hover and keyboard:** hover opens after 80 ms and closes after a 250 ms grace.
    Enter on a mark opens it and focuses Restore; Tab is trapped inside; Esc returns
    focus to the mark.
  - **Page pill:** "Hoot changed N things · Undo all · Pause on this site", in a polite
    live region. The paused state shows Resume and auto-hides after 5 s.
  - **Ask-first chip:** pressing it keeps the page selection (`mousedown` default is
    prevented).
  - **Thinking shimmer:** shown on the span's rects only; a static tint with reduced
    motion.
- Motion: a critically damped spring baked into a CSS `linear()` easing, with a
  `cubic-bezier(0.2,0,0,1)` fallback. The swap is 90 ms blur-out of the original, then
  90 ms blur-in of the rewrite; restore runs the same path backwards. Reduced motion uses
  a 120 ms opacity fade only. The popover, pill and chip use one interruptible WAAPI
  animation each (`reverse()` from the current point).
- Keyboard map: Alt+Z undoes the last change, Alt+Shift+Z undoes all, Alt+H pauses or
  resumes. **Alt+L asks while the chip is visible (my addition, so keyboard users can
  reach the chip; please confirm or rename in the spec).** Matching uses `event.code`,
  so AZERTY layouts and macOS Option-characters work. Shortcuts are ignored while typing,
  with Ctrl or Meta held, and (by default) for untrusted synthetic events.
- Copy: Chrome's native copy picks up the shadow-DOM rewrite, so `CopyController`
  intercepts copies that touch a mark. It writes the original (default) or what the
  reader sees (`visible`), using a block-aware serializer that collapses whitespace like
  `innerText` (one break per block, two per `p`). Only `text/plain` is written. Overlay
  marks never change the page, so native copy already gives the original; `visible` mode
  doesn't apply to them yet.
- Verified in Chromium 156 (light, dark, `prefers-contrast: more`, reduced motion): chip →
  Alt+L → shimmer → animated swap → pill, hover popover, Enter/Esc focus, Ctrl+C gives
  the original, Alt+Z gives byte-identical `innerHTML`, and Alt+H shows the paused state.
- Selection (D2-13):
  - **`settled`:** fires 300 ms after the last `selectionchange` with the pointer up
    (never mid-drag). It feeds the Ask-first chip.
  - **`dwell`:** fires at 1.2 s since the last change (s3). A copy event cancels dwell and
    sets `copied` (s2), plus `afterSettle` when it lands within 2.5 s.
  - **Reselection (s4):** session-scoped; the same normalized span seen again sets
    `reselected`.
  - **Size class (s1):** term ≤ 3 words, phrase ≤ 10, sentence ≤ 80; across blocks or
    longer is multi-paragraph.
  - **Cooldowns (s10):** typing keys or a scroll ≥ 2500 px/s hold settle and dwell until
    1 s after the last one.
  - **Ignored:** selections in form fields or contenteditable, and in Lens UI or marks.
- Context: `span` is whitespace-normalized and ≤ 600 characters. `paragraph` is the
  closest block, windowed around the span to ≤ 1500 characters with "…" on cut sides; it
  reads through inline marks, so it's always the page's original text. `headingPath` is
  the h1→h3 chain before the span, `title` is ≤ 200 characters, and `lang` comes from the
  closest `[lang]`, then `<html lang>`. `siteCategory` and the registrable domain are
  left to the service worker (D2-20) and C-23. Signals s5–s9 are D2-30, which needs C-22.
- Verified in Chromium 156: mouse drag (nothing fires mid-drag), Shift+Arrow extension of
  a selection, copy, and reselection.

- MV3 skeleton (D2-15):
  - **Manifest:** permissions are only `storage`. Content scripts run on
    http/https/file in all frames, plus about:blank and srcdoc frames via
    `match_origin_as_fallback`. `incognito: not_allowed` (spec §11). More permissions
    get added with the features that need them.
  - **Shadow roots:** `dist/dev` uses open roots and the dev upstream, with Lens on by
    default. `dist/prod` uses closed roots, Lens off until the app enables it (consent
    first), and no stub. Sizes: content 55 KB minified (18 KB gzipped, inside D2-40's
    50 KB budget), sw 4.6 KB.
  - **Message boundary:** the service worker answers only its own extension's content
    scripts (`sender.id` and `sender.tab` checked) and validates every message.
    Rewrites are refused while Lens is off. Each `reqId` is tracked per tab and can be
    cancelled.
  - **Content script:** when the extension context is invalidated (extension reload),
    the old content script restores the page and tears itself down.
  - **Per-site pause:** keyed by `location.hostname`, so subdomains are separate sites
    for now. Proper registrable domains need the Public Suffix List (D2-20).
  - **Password pages:** any `input[type=password]` turns Lens off for the page
    (`pageBlockReason`).

  - The weak-marker threshold was too high for a React page ticking once a second; it
    now treats `#root` or `#app` plus any mutation as dynamic.
