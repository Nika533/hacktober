## For d3: the `Renderer` contract (from `@hoot/lens-dom`)

`pdf-view`'s overlay renderer should implement `Renderer` from
`packages/lens-dom/src/render/types.ts`:

- `check(range, spec?)`: returns `{ ok: true }` or `{ ok: false, reason }`.
- `apply(range, spec, { animate? })`: returns a `Mark` or `null`.
- `restore(id, { animate? })`, `restoreAll()`, `get(id)`, `marks()`,
  `subscribe(listener)` for `dropped` and `reapplied` events, and `destroy()`.

A `Mark` has `id`, `spec`, `original` (the exact characters), `anchor` (the focusable
element the popover anchors to, with `aria-describedby` set) and `rects()`.

`MarkSpec` is `{ action: RenderAction, transform, text, highStakes?, placement? }`. The
Lens UI only talks to `Renderer` and `Mark`, so a PDF renderer gets the popover, pill and
keyboard map for free. The Reader can call `createLens({ document, backend, site: '',
surface: 'reader', renderer })` with its IPC `LensBackend`, where `renderer` is
`new PdfOverlayRenderer({ scale: () => view.scale })` in pages mode and `'inline'` in
reflow mode. Recreate the Lens when the mode changes, as `apps/extension/src/viewer` does.

## Notes

- Contracts: lens-dom and the extension import types, `TRANSFORM_RULES`, `LENS_LIMITS`,
  `countWords`, `MAX_REPLACE_WORDS`, `LensBackend` and `LensBackendError` from
  `@hoot/core`. The service worker validates every content-script message with
  `@hoot/core/schemas` (`RewriteRequestSchema`, `LensContextSchema`, `LensEventSchema`,
  `LensSettingsPatchSchema`, `IdSchema`). The content script never imports zod
  (content.js is 58 KB minified, 20 KB gzipped). Controller tests parse every context and
  event that leaves the page with core's schemas.
- Context and events: `site` is core's `registrableDomain()` of the host (`''` for
  files; srcdoc and about:blank frames use the origin they inherit). `urlHash` is FNV-1a 64 over
  `salt|origin+pathname`; the salt is random per install in `chrome.storage.local`, and
  query strings are never hashed. `lang` falls back to `und`. Signals s1–s6 and s9 are
  real (s6 without frequency lists yet); s8 is null until C-22; s7 uses the profile's
  `knownTerms`.
- `kept` (`src/kept.ts`): a change counts as kept when it stays 30 s without a revert and
  the reader either scrolled past it (its bottom went above the viewport) or had it on
  screen for 30 s in total while the tab was visible. I read "scrolled past the
  paragraph" as "scrolled past the change", because the overlay and PDF renderers only
  expose the change's rects. Time is counted in 1 s ticks that only run while changes
  are tracked; a change the page re-renders keeps its history, and one that disappears
  for 30 s is dropped. Restore, "I knew this", Undo all and pausing stop tracking.
- Settings: the service worker keeps `LensSettings` in `chrome.storage.local` (validated
  with `LensSettingsSchema`, patched with `applySettingsPatch`). Changes are pushed to
  every tab. Per-site pause is `sites[site] = 'paused'` through `settings.patch`;
  `never` turns Lens off for the site. Production defaults to `DEFAULT_LENS_SETTINGS`
  (off until consent); `--mode e2e` defaults to on in `ask` mode. Stored settings that
  don't match the current schema (an older or newer version, e.g. once C-22 adds
  `riskOverrides`) go through `migrateSettings`, so valid fields such as the site rules
  survive instead of resetting to the defaults.
- Options page (`src/options`): talks to the service worker through the same
  `ExtensionBackend` as the content script (`lens.settings.get` / `lens.settings.patch`),
  so it keeps working when settings move to the app with D2-20. The router also answers
  our own extension pages, settings patches are applied one at a time (two quick changes
  used to lose one), and the service worker pushes `lens.settings.changed` to extension
  pages as well as tabs, so Alt+H on a page shows up in an open options page. Changes are
  optimistic; a failed save rolls back with a toast. Removing a site offers Undo and moves
  focus to the next row. Typed sites are normalised like the content script's `site`
  (`https://www.Example.com/a` → `example.com`).
- Builds: `npm.cmd run build` gives the production extension in `apps/extension/dist`
  (closed shadow roots, no fake; zero fake references in `sw.js`). `build:e2e` and `e2e`
  build the same folder with core's fake, open shadow roots and an "(e2e)" name. Load
  `apps/extension/dist` unpacked; the manifest `key` gives the stable dev ID.
- Mark structure: the selected nodes move into a `<hoot-lens-mark>` element and stay in
  the light DOM. Its shadow root renders the rewrite (replace) or a `<slot>` plus the
  note (gloss), so the page's `textContent` never changes, restoring means unwrapping,
  and the original `Text` node objects come back. Rewrites are always set with
  `textContent`, never parsed as HTML.
- Never touched (`src/guard.ts`): inputs, textarea, select, button, `contenteditable`,
  textbox-like roles, `pre`, `code`, `kbd`, `samp`, `blockquote`, `q`, `hidden`, `inert`,
  `aria-hidden`, scripts and styles, iframes, media, `svg`, `math`, existing marks, our
  own UI, and the whole page when it has a password field. Ranges stay inside one block
  and ≤ `LENS_LIMITS.span`.
- Interpretation to confirm (spec §5.4, "text inside links' accessible names"): link
  text is never replaced, and neither is a range that starts or ends inside a link. A
  gloss may cover a whole link.
- Re-render handling: marks that the page changes are unwrapped quietly (`dropped`) and
  re-applied when a block with the same text returns (`reapplied`), at most 3 times per
  mark. Dynamic pages use the overlay renderer. Strong markers mean dynamic, as does
  ≥ 8 mutations/s in the first 3 s, or `#root`/`#app` plus any mutation. Two inline
  drops switch the page to overlay.
- Overlay renderer: a live `Range` plus `::highlight()` hides the original glyphs. The
  rewrite box copies the page's typography and follows the paragraph flow. If it doesn't
  fit, it shrinks to 94/88/82 % and then becomes a floating card (spec §9.2). Limits:
  screen readers still read the original in place, and the box sits at the end of the
  tab order.
- Selection: `settled` fires 300 ms after the last change with the pointer up, and
  `dwell` at 1.2 s. Copy sets `copiedWithinMs` and cancels dwell. `reselectCount` is
  session-scoped. Size classes: term ≤ 3 words, phrase ≤ 10, sentence ≤ 40
  (`MAX_REPLACE_WORDS`), passage above that, and multi-paragraph across blocks.
  Typing or a ≥ 2500 px/s scroll holds everything for 1 s.
- Keyboard map: Alt+Z, Alt+Shift+Z and Alt+H. **Alt+L asks while the chip is visible;
  this is my addition, so please confirm it in the spec.** Matching uses `event.code`.
  Shortcuts are ignored while typing and for untrusted events.
- Motion: a critically damped `linear()` easing, a 90 + 90 ms blur swap that restore
  reverses, 120 ms opacity with reduced motion, and interruptible WAAPI presence for the
  popover, pill and chip.
- Copy: `CopyController` intercepts copies that touch a mark, because Chrome's native copy
  would include the shadow-DOM rewrite. It writes the original or what the reader sees
  (`copyBehavior`) as `text/plain`, with innerText-like whitespace.
- Verified in Chromium 156 (`npm.cmd run e2e:extension`, 15 tests, all through the bridge
  client to C-13's fake protocol server):
  - Ask-first swap, popover and exact restore, with `shown` and `reverted` feedback.
  - Copy gives the original.
  - Never offered on code, quotes, editables, link text or password pages.
  - Alt+L, Alt+Z, and Alt+H with the pause surviving a reload.
  - React page uses the overlay and follows re-renders.
  - Runs inside same-origin, cross-origin and srcdoc frames; srcdoc frames follow the parent site's pause.
  - Options page: a Never rule keeps Lens off an open page, removing it brings Lens
    back, Alt+H on the page shows up as Paused, and axe passes in light and dark.
  - The Lens UI passes axe in light, dark and high contrast.
  - Auto mode (set from the options page) rewrites a foreign-language sentence after the
    dwell and leaves an ordinary word alone.
  - The options page shows "Connected to Hoot …", and "Hoot isn't running" once the app
    goes away.
- Demo: `npm.cmd run demo -w @hoot/lens-dom`, then open
  `packages/lens-dom/demo/dist/index.html` (`?renderer=overlay`, `&action=gloss`,
  `&stakes`, `&copy=visible`, `&delay=ms`).
- Playwright needs `npx.cmd playwright install chromium`. The extension specs launch
  `channel: 'chromium'`, because headless-shell can't load extensions.
