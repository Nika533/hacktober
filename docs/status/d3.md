## Now

- **D3-30 `packages/pdf-view`, part 1: in review** (PR #5, branch
  `d3/D3-30-pdf-view`, stacked on #4). The parts that don't need d2's
  `Renderer`:
  - `openPdf()` (PDF.js 6.4.299, XFA off; PDF.js 6 doesn't use eval, so
    strict CSPs work) and `PdfView`, which is framework-free so d2's extension
    viewer and the Reader share it.
  - **Pages mode:** pages render lazily one screen ahead at the device pixel
    ratio. Each page has a selectable PDF.js text layer, checked to line up
    with the glyphs. Fit-width and zoom; the old bitmap stays up until the
    sharp one is ready. Off-screen canvases are released (LRU, 12 pages).
  - **Reflow mode ("Text only"):** the pure `reflowPage()` turns text runs into
    h2/h3/p blocks. It rejoins wrapped lines, undoes line-end hyphens and keeps
    stream order so columns stay apart. Rendered with text nodes only, as
    plain selectable DOM that lens-dom can mark directly. The document's
    `/Lang` is applied.
  - 12 tests, including one against real PDF.js output on a generated fixture
    PDF. A browser check (`npm.cmd run shots`) verifies the text layer is
    selectable and aligned, zoom re-renders sharp, fit-width doesn't
    overflow, and the reflow headings. axe: 0 violations in light and dark,
    both modes.
- **D3-10 shared chat UI: in review** (PR #4, branch `d3/D3-10-chat-ui`,
  stacked on #3).
  - Markdown, Transcript, Composer, AttachmentsRow, QuickChips,
    ClipboardChip, ErrorBody and a Chip primitive, all in `packages/ui`.
  - Prop-driven: no `window.hoot` and no IPC inside. Hosts pass callbacks
    (`onSend`, `onStop`, `onRegenerate`, `onPin`, `onCopy`, `onOpenLink`,
    `onAddKey`, …) and small view types (`ChatMessageView`,
    `ChatAttachmentView`).
  - Markdown is safe: no raw HTML, only http(s) and mailto links, and
    images are shown as links, never fetched. Code blocks have Copy.
  - Transcript follows new text only while you're at the bottom, offers
    "Jump to latest" otherwise, and goes back to the bottom when you send. It
    announces "Hoot answered", stops and errors once, never the tokens.
  - ErrorBody covers every Gemini error code from `main/ai/errors.ts`, each with
    one fix. A rejected key mentions that Argon needs a paid tier.
  - Gallery "Chat" section: a Buddy-card-sized chat on fake streaming, plus
    every error state. axe finds 0 violations at rest and mid-stream. 50
    unit tests in total.
  - Fixes a D3-00 bug: a tooltip opened by keyboard focus vanished when Tab
    scrolled its button into view. It now follows the trigger on scroll and
    only hides once the trigger leaves the screen.
- **D3-00 `packages/ui` design system: in review** (PR #3, branch `d3/D3-00-design-system`).
  - Tokens declared once with `light-dark()`. Theme follows the OS unless the
    host sets `<html data-theme>`. High contrast (`prefers-contrast: more`),
    Windows forced colours, reduced transparency and reduced motion each
    change a few settings instead of re-declaring the palette.
  - Materials (chrome, pane, card, popover, chip), the Segoe UI Variable type
    ramp, spacing, radius, elevation, spring presets (TS and CSS

  - Components: Owl (all six moods), Button, IconButton, Segmented (native

  - Gallery at `#/gallery` (`npm.cmd run gallery` in `packages/ui`).
    `npm.cmd run shots` takes light, dark, high-contrast and more-contrast
    screenshots and runs axe (WCAG 2.2 AA) on light and dark, with and without
    the dialog open: **0 violations**.
  - 31 unit tests (happy-dom). Typecheck and eslint are clean.

## Notes

### Using `@hoot/ui` (d1: Buddy, capture, note)

```tsx
import '@hoot/ui/styles.css'
import { HootUIProvider, applyTheme, applyAccent } from '@hoot/ui'

applyTheme(state.system.darkMode ? 'dark' : 'light') // or 'system'
applyAccent(state.system.accentColor) // '#RRGGBB' or Electron's 'RRGGBBAA'; null resets
// If Windows transparency effects are off and the media query doesn't fire:
document.documentElement.dataset.transparency = 'reduce'

root.render(<HootUIProvider><App /></HootUIProvider>)
```

- `Owl` no longer reads `window.hoot`. Pass `gaze={{ x, y }}` (cursor offset
  from the owl centre) and bump `talkSignal` on each `chat:delta`. Without
  `talkSignal` a talking owl flaps its beak on a steady beat. Under reduced
  motion each mood keeps a still pose (thinking tilts, listening perks its
  tufts, celebrate shows a still ring, error squints), so moods stay readable.
- `IconButton` and `Button` pass every other prop through to the `<button>`,
  so `data-hit` for click-through still works.
- Text is selectable by default. Add `.hoot-chrome` to chrome that shouldn't
  be. Legacy set `user-select: none` globally.
- Overlays: `useToast().show({ message, action: { label: 'Undo', onAction } })`
  and `await useConfirm()({ title, confirmLabel, tone: 'danger' })`.

### Buddy card with the chat components (d1, D1-15)

```tsx
<Transcript
  messages={session.messages.map(toView)} // see Requests 5
  onRegenerate={() => hoot.chat.regenerate()}
  onPin={(id) => hoot.pins.create(id)}
  onCopy={(t) => hoot.clipboard.writeText(t)}
  onOpenLink={(href) => hoot.openExternal(href)}
  onAddKey={() => hoot.windows.openSettings()}
/>
{hint && <ClipboardChip kind={hint.kind} chars={hint.chars} armed={!!hint.selected}
  onToggle={hoot.clipboard.arm} onDismiss={hoot.clipboard.dismiss} />}
<AttachmentsRow attachments={pending} onRemove={hoot.capture.removeAttachment} />
{pending.length > 0 && <QuickChips actions={QUICK} onPick={(id) => hoot.chat.send({ quickAction: id })} />}
<Composer streaming={streaming} onSend={(text) => hoot.chat.send({ text })}
  onStop={hoot.chat.stop} onEmptySend={pending.length ? () => hoot.chat.send({ quickAction: 'explain' }) : undefined}
  actions={<IconButton label="Circle anything" size="sm"><PencilLine /></IconButton>} />
```

- The `hoot.*` names above are placeholders until C-02 freezes `HootApi`.
- `Transcript` fills its flex parent (`flex: 1; min-height: 0`). Give the
  card a fixed height and a column layout.
- Stream deltas by updating `text` on the message. Markdown is memoised per
  message, so only the streaming message re-renders.
- Remount `Composer` with a new `key` to reseed it (for "Explain more"
  pre-fill).

### Design decisions

- **Windows first, Apple motion.** Controls follow Windows 11: the dialog
  footer puts the primary action first with equal-width buttons on a recessed
  band, the default cursor stays an arrow, and the type is Segoe UI Variable
  (Display, Text and Small optical families). Motion follows the apple-design
  skill: critically damped springs, feedback on pointer-down, and enter and
  exit along the same path.
- **The owl is the one bold element.** Everything else is quiet and neutral,
  and the accent is the user's Windows accent. `onAccentFor()` picks a text
  colour that passes AA on any accent.
- **Native first.** Segmented uses radios, Switch uses a checkbox with
  `role="switch"`, Slider uses a range input, and Dialog uses `<dialog>`, so
  keyboard support, screen-reader semantics and focus containment come from
  the platform.
- **Focus on destructive confirms goes to Cancel.** A confirm only appears
  for irreversible actions; everything else should use Undo toasts.
