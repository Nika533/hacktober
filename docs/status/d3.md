### Buddy transitions: what the renderer expects from main (d1, F-D1-1)

The reference is `createFakeBuddyMain` in `packages/ui/src/gallery/fakeBuddyMain.ts`.

- **Grow** (dot → pill → card): resize the window and patch `buddy.layout`
  (and `mode`) first, then send `buddy:transition`. The renderer mounts the
  new surface once a layout of that mode's size arrives (it gives up waiting
  after 250 ms), animates it in, then calls `transitionDone(id)`.
- **Shrink** (and → hidden): send the transition while the window is still
  big. The renderer animates out, acks, and then main resizes and patches.
- Only the **latest** id is acked. A newer transition supersedes one that's
  still animating, and the animation turns around from wherever it is on
  screen. A transition to the mode the renderer already shows is acked at once.
- A fallback acks 900 ms after the transition even if no frame ever ran
  (an occluded window). If the slice's `mode` changes and no transition
  follows within 400 ms, the renderer follows the slice without acking.
- Layouts: the card fills the window (8 DIP inset); the owl, capsule and
  greeting are placed from `layout.owl` and `openX`/`openY`. Hit regions are
  window-local CSS px (= DIP at zoom 1).
- The renderer calls `setCursorTracking(true)` whenever it shows the owl
  (false under reduced motion).

### Design decisions

- **Windows first, Apple motion.** Windows 11 control conventions (dialog
  footer, arrow cursor, Segoe UI Variable optical families) with the
  apple-design skill's springs, feedback on pointer-down, and symmetric
  enter and exit.
- **The owl is the one bold element.** The accent is the user's Windows
  accent, and `onAccentFor()` keeps text on it at AA contrast.
- **Native first.** Segmented, Switch, Slider and Dialog are built on radios,
  a checkbox, a range input and `<dialog>`.
- **Destructive confirms focus Cancel.** Use Undo toasts for everything
  reversible.
